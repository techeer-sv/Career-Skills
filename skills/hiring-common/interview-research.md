# 회사별 면접·코딩테스트 후기 리서치 모듈 (공용)

특정 회사/포지션의 코딩 테스트나 면접을 **그 회사 실제 전형에 맞게** 준비·시뮬레이션하기 위한 리서치 방법론이다.
`hiring-sim-coding-test`, `hiring-sim-interview`, `hiring-prep-interview`가 공유한다.

핵심 원칙: **리서치로 회사 실제 정보가 나오면 그 정보 + 이력서·포트폴리오·공고로, 안 나오면 이력서·포트폴리오·공고만으로** 준비한다. 후기는 회사가 어떻게 검증하는지를 알려주는 최고의 단서다. 특히 **라이브 코딩/코드 리뷰 스타일**은 후기에서만 나오는 경우가 많다.

---

## 언제 실행하는가

사용자가 **특정 회사/공고**를 지정했을 때만 실행한다(일반 연습이면 생략). 공고 URL·회사명·포지션 중 하나라도 있으면 리서치를 시도한다.

리서치 도구: `WebSearch`/`WebFetch`로 직접 조사한다. `/autoresearch`나 `researcher` 계열 서브에이전트가 있으면 병렬 위임하고, 없으면 웹 검색으로 폴백한다(graceful fallback). 채용 사이트가 봇 차단(403)이면 브라우저 User-Agent로 페이지를 받아 임베드 JSON(`__NEXT_DATA__` 등)에서 본문을 추출한다.

## 소스 (Tier별)

| Tier | 소스 | 캐낼 것 |
|---|---|---|
| 1 구조화 후기 | 잡플래닛, 캐치(catch), 블라인드, 링커리어, 잡코리아 면접후기 | 전형 단계, 면접 난이도·분위기, 합·불, 질문 요약 |
| 2 개인 경험 블로그 | velog, tistory, medium, brunch, github.io | **라이브 코딩/코드 리뷰 재현, 실제 질문 원문, 코테 문제 유형** (가장 상세) |
| 3 커뮤니티 | 취업 카페(스펙업 등), 디스콰이엇, 레딧(외국계), 유튜브 면접 후기 | 최신 경험담, 프로세스 변경 여부 |
| 4 공식 | 회사 기술블로그의 채용/면접 프로세스 글, 공고의 전형 절차 | 공식 전형 단계, 코테 플랫폼 |

검색 쿼리 패턴(회사·직무 대입, 한/영 병행):
`"[회사] [직무] 면접 후기"` · `"[회사] 코딩테스트 후기"` · `"[회사] 라이브 코딩"` · `"[회사] 코드 리뷰 면접"` · `"[회사] 기술면접 질문"` · `"[company] interview experience"` · `site:velog.io [회사] 면접` · `site:tistory.com [회사] 코딩테스트`

## 추출 스키마 (구조화해 저장)

```
전형 단계:        서류 → 코테 → 1차(기술) → 2차(임원/컬처) → ...
코딩 테스트:      플랫폼(프로그래머스/해커랭크/자체), 유형(알고리즘/구현/SQL/과제),
                 문항 수·시간, 난이도, 통과 커트라인 언급
기술 면접:        라이브 코딩 여부 / 코드 리뷰 여부·스타일 / CS 질문 범위 /
                 프로젝트 딥다이브 깊이 / 시스템 설계 여부
라이브 코드 리뷰:  대상(본인 제출 코드·과제·즉석 문제), 어떤 지적/질문이 들어오는지,
                 리팩터링·트레이드오프·테스트 요구 여부  ← 있으면 최우선으로 재현
인성/컬처:        질문 스타일, 회사 가치 연계, 임원 면접 관점
자주 나온 질문:    실제 질문 예시(요약 인용 + 출처 tier)
분위기·난이도·팁:  압박 여부, 소요 시간, 후기 작성 시점
```

### jobclaw 3역할 면접관 렌즈 (면접 라운드 해석용)

후기의 각 라운드를 아래 역할로 매핑하면 무엇을 검증하는지 선명해진다.

- **TECH (현업 시니어)** — 직무 전문성·문제 해결·기술 깊이. 라이브 코딩/코드 리뷰가 여기서 나온다.
- **HR (인사)** — 컬처핏·협업·성장 가능성·커리어 비전.
- **EXEC (임원 최종)** — 전략적 사고·리더십·비즈니스 임팩트. 국내 다수 기업의 2차 면접.

## 신뢰도 관리

- **교차 확인**: 2개 이상 후기에서 반복되는 패턴만 "높음"으로 취급. 단일 후기는 "참고"로 표시.
- **시점 주의**: 2년 이상 지난 후기는 전형이 바뀌었을 수 있음을 명시. 최신 후기 우선.
- **주관성**: 후기는 개인 1인 경험. "난이도 어려움" 같은 주관 표현은 상대적으로 해석.
- **개인정보 금지**: 후기 작성자 실명·신상, 블라인드 내부 뒷담화는 인용하지 않는다. 질문 유형·전형 구조 같은 **사실 정보만** 사용.

## Graceful Degradation 프로토콜 (필수)

리서치 결과에 따라 준비 모드를 자동 전환한다. 어느 모드인지 사용자에게 **명시**한다.

| 리서치 결과 | 모드 | 준비 방식 |
|---|---|---|
| 충분한 후기 발견 (교차 확인됨) | **회사 재현 모드** | 후기 기반 코테 유형·난이도·라이브 코드리뷰 스타일 + 실제 나온 질문 유형 + 이력서·포폴·공고 |
| 일부만 발견 | **혼합 모드** | 발견된 조각(예: 코테 플랫폼만 확인)은 반영, 나머지는 공고+직무 일반 패턴 |
| 후기 없음/접근 불가 | **폴백 모드** | 이력서·포폴·공고 기반 일반 [직무] 기준으로 진행. "이 회사 후기를 찾지 못해 일반 기준으로 진행합니다" 고지 |

폴백은 실패가 아니다. 후기가 없어도 공고의 담당업무·기술스택·자격요건과 이력서·포폴만으로 충분히 맞춤 준비가 가능하다. 없는 회사 정보를 지어내지 않는다.

