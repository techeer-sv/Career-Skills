# 면접 대비 문서 생성기 (Hiring Interview Prep)

채용공고 URL(또는 붙여넣기)을 입력받아, 웹 리서치를 통해 실제 면접 후기와 예상 질문을 수집하고,
자기소개부터 컬처핏까지 커버하는 **맞춤형 면접 대비 마크다운 문서**를 생성합니다.

---

## 핵심 특징

```
- 실제 후기 기반: 잡플래닛, 잡코리아, 캐치, 블라인드 후기 리서치
- 포지션 맞춤: 채용공고 요구사항 분석 → 기술 질문 커스터마이징
- <details> 답변 가이드: 각 질문에 펼침형 답변 가이드 포함
- 자기완결형 문서: 이 문서 하나로 면접 전 준비 완료
```

---

## 실행 절차

### Step 1: 채용공고 입력

"준비할 채용공고의 URL 또는 내용을 붙여넣어주세요."

- URL 제공 시: `WebFetch`로 공고 내용을 가져온다. 실패하면 "URL에서 내용을 가져오지 못했습니다. 내용을 직접 붙여넣어주시면 이어서 진행합니다."
- 직접 붙여넣기 시: 그대로 사용
- 미제공 시: "채용공고는 필수입니다. URL 또는 내용을 입력해주세요." 후 대기

### Step 2: 채용공고 분석

입력된 공고를 파싱하여 다음 정보를 추출한다:

```
- 회사명
- 포지션명
- 고용 형태 (신입/경력/무관)
- 업무 내용
- 필수 자격 요건 (Must-have)
- 우대 자격 요건 (Nice-to-have)
- 기술 스택 (언급된 언어, 프레임워크, 인프라, 도구)
- 기타 특이사항 (회사 특성, 문화 키워드)
```

추출 결과를 사용자에게 간략히 보여주고 진행 의사를 확인한다:

```
분석 완료:
- 회사: [회사명]
- 포지션: [포지션명]
- 기술 스택: [목록]

이 정보를 바탕으로 면접 대비 문서를 생성합니다. 시작할까요?
(틀린 내용이 있으면 수정 내용을 알려주세요.)
```

### Step 3: 웹 리서치 (핵심 단계)

이 단계가 문서의 품질을 결정한다. 가능한 많은 소스에서 데이터를 수집한다.
각 검색/조회가 실패해도 오류 없이 계속 진행하고, 수집된 정보만으로 문서를 완성한다.

#### 3-1. 면접 후기 수집

아래 검색어로 `WebSearch`를 수행한다 (순서대로, 실패해도 다음으로 넘어감):

```
1. "{회사명} 면접 후기"
2. "{회사명} {포지션} 면접 질문"
3. "{회사명} 면접 분위기"
```

검색 결과에서 잡플래닛(jobplanet.co.kr), 잡코리아(jobkorea.co.kr), 캐치(catch.co.kr), 블라인드(teamblind.com), 링커리어(linkareer.com) 등 후기 사이트 URL을 식별한다.

식별된 URL에 대해 `WebFetch`를 시도한다. 실패(차단, 로그인 필요 등)하면 검색 스니펫의 텍스트만 활용한다.

수집 대상 정보:
- 면접 형태 (1:1, 패널, 토론, 다대일 등)
- 면접 시간 (분)
- 면접 분위기 (편안함/압박/보통)
- 면접 난이도 (1~5점)
- 자주 나온 질문 패턴
- 합격/불합격 후기에서 공통으로 언급되는 키워드

#### 3-2. 포지션별 기술 질문 수집

```
1. "{회사명} {포지션} 기술 면접 질문"
2. "{포지션} 면접 질문" (일반 포지션 기준)
3. "{주요 기술스택} 면접 질문" (기술 스택이 명확한 경우)
```

#### 3-3. 회사 정보 수집

```
1. "{회사명} 기업 정보"
2. "{회사명} 기술 블로그" 또는 "{회사명} tech blog"
3. "{회사명} 핵심 가치" 또는 "{회사명} 기업 문화"
```

회사 공식 웹사이트나 기술 블로그가 검색되면 `WebFetch`로 추가 정보를 수집한다.

수집 대상 정보:
- 주요 사업 영역 및 제품/서비스
- 사용 기술 스택 (기술 블로그에서 확인)
- 회사 문화 및 핵심 가치
- 최근 이슈 또는 전략적 방향

#### 3-4. 리서치 요약 (내부용)

수집된 모든 정보를 다음 형식으로 정리한다 (문서 생성에 사용, 사용자에게는 미출력):

```
[면접 메타 정보]
- 형태: [수집된 정보 / 확인 불가]
- 시간: [수집된 정보 / 확인 불가]
- 분위기: [수집된 정보 / 확인 불가]
- 난이도: [수집된 정보 / 확인 불가]
- 후기 출처: [사이트명 + 건수]

[자주 나온 질문 패턴]
- [질문1]
- [질문2]
...

[회사 특화 정보]
- 사업 영역: [정보]
- 기술 스택: [정보]
- 핵심 가치: [정보]

[리서치 한계]
- 차단된 사이트: [목록]
- 정보 부족 영역: [목록]
```

### Step 4: 문서 구조 설계

Step 2의 공고 분석과 Step 3의 리서치 결과를 바탕으로 문서 섹션을 설계한다.

#### 섹션 구성 원칙

```
필수 섹션 (항상 포함):
  1. 자기소개 & 지원동기
  2. 핵심 기술 질문 (기술 스택 기반, 최소 5개)
  3. 인성/컬처핏 질문 (최소 4개)
  4. 면접 팁
  5. 역질문 예시
  6. 참고 링크

조건부 섹션 (정보가 충분할 때만 포함):
  - 도메인 특화 질문: 회사의 사업 영역(보안/금융/커머스 등)에 특화된 질문 포함
  - 시스템 설계 질문: 시니어 포지션 또는 아키텍처 역할이 명시된 경우
  - 회사 특화 질문: 회사 특유의 문화/가치/방법론과 연관된 질문
```

#### 기술 질문 우선순위

채용공고의 기술 스택과 업무 내용을 분석하여 질문 우선순위를 결정한다:

```
가중치 산정:
1. 필수 자격 요건에 명시된 기술 → 최우선
2. 우대 자격 요건에 명시된 기술 → 차순위
3. 업무 내용에서 반복 언급된 키워드 → 차순위
4. 실제 후기에서 자주 나온 질문 → 필수 포함
```

### Step 5: 문서 생성

Step 2~4의 분석을 바탕으로 마크다운 문서를 생성한다.

#### 문서 헤더 형식

```markdown
# {회사명} [{고용형태}] {포지션명} — 면접 준비 가이드

> **면접 형태**: [수집된 정보 / 미확인]
> **면접 특성**: [수집된 분위기 / 미확인]
> **면접 난이도**: [X.X/5.0 (출처) / 미확인]
> **참고 출처**: [수집된 출처 목록. 예: 잡플래닛 XX건, 잡코리아 XX건 등]

---
```

#### 목차 형식

```markdown
## 목차

1. [자기소개 & 지원동기](#1-자기소개--지원동기)
2. [{기술 섹션 제목}](#2-...)
3. [{도메인 섹션 제목}](#3-...) [조건부]
4. [{시스템 설계 제목}](#4-...) [조건부]
5. [인성/컬처핏 질문](#N-인성컬처핏-질문)
6. [회사 특화 질문](#N-회사-특화-질문) [조건부]
7. [{회사명} 특수성 정리](#N-특수성-정리) [조건부]
8. [면접 팁](#N-면접-팁)
9. [참고 링크](#N-참고-링크)

---
```

#### 질문 블록 형식

각 질문은 다음 형식으로 작성한다:

```markdown
### Q{번호}. {질문 내용}

<details>
<summary>💡 답변 가이드</summary>

**{핵심 포인트 또는 구조 안내}**

{답변 가이드 내용}

> "예시 답변 문구" (있는 경우)

**꼬리질문 대비:**
- "{예상 꼬리질문}"
- "{예상 꼬리질문}"

</details>

---
```

#### 섹션별 작성 가이드

**1. 자기소개 & 지원동기 섹션**

포함할 질문 유형:
- 자기소개 (1분/3분)
- 회사 지원 이유
- 포지션 지원 이유
- 회사/제품 인지도 확인 ("알고 있는 제품/서비스는?")
- 직무 선택 이유

각 질문의 답변 가이드에 포함할 내용:
- 회사와 포지션에 특화된 답변 방향
- 피해야 할 답변 유형
- 리서치에서 수집한 회사 가치/사업 방향 연결 포인트

**2. 핵심 기술 질문 섹션**

포함 원칙:
- 공고의 필수 기술 스택마다 최소 1개 이상의 질문
- 실제 후기에서 수집된 질문은 반드시 포함
- 원리/동작 방식 → 실무 경험 → 트레이드오프 순의 깊이 구성
- 코드 예시가 효과적인 경우 코드 블록 포함

답변 가이드에 포함할 내용:
- 기술 개념 요약 (핵심만)
- 실무 경험 연결 방법 (STAR 활용)
- 꼬리질문 2~3개 대비
- 비교 대안 기술이 있으면 비교표 포함

**3. 도메인 특화 질문 섹션 (조건부)**

회사의 사업 영역이 특수한 경우에만 포함.
예: 보안 기업 → 보안 개념, 금융 기업 → 금융 도메인, 커머스 → 대규모 트래픽/결제

**4. 시스템 설계 섹션 (조건부)**

시니어(3년 이상) 포지션이거나 아키텍처 업무가 명시된 경우에만 포함.
질문은 포지션의 실제 업무 영역에 맞춘 설계 문제로 구성.

**5. 인성/컬처핏 질문 섹션**

STAR 기법 기반 질문:
- 협업/갈등 경험
- 주도적으로 문제를 해결한 경험
- 실패와 학습
- 성장 방법 / 기술 학습 방식
- 커뮤니케이션 경험

각 답변 가이드에 STAR 구조(상황-과제-행동-결과) 명시.

**6. 회사 특화 질문 섹션 (조건부)**

리서치에서 회사 특유의 면접 패턴이 확인된 경우에만 포함.
예: 특정 방법론을 강조하는 회사, 특정 가치를 반드시 묻는 회사 등.

**7. 특수성 정리 섹션 (조건부)**

포지션이나 회사가 일반적이지 않은 특수성을 가진 경우에만 포함.
예: 보안 SW 배포, 핀테크, 의료 등 규제 산업, 글로벌 서비스 등.

비교표 형식으로 일반 포지션과의 차이점을 정리한다.

**8. 면접 팁 섹션**

필수 포함 항목:
- 실제 후기 기반 팁 (리서치 결과 활용)
- 예상 시간 배분표
- 역질문 예시 3~5개

형식:
```markdown
## {N}. 면접 팁

### 실제 면접 후기 기반 팁

1. [팁 1]: [구체적 설명]
2. [팁 2]: [구체적 설명]
...

### 예상 시간 배분

| 구간 | 시간 | 내용 |
|------|------|------|
| ...  | ...  | ...  |

### 역질문 예시

- "[역질문 1]"
- "[역질문 2]"
- "[역질문 3]"
```

**9. 참고 링크 섹션**

리서치에서 실제로 접근을 시도한 URL을 모두 나열한다.
WebFetch가 차단된 경우에도 링크는 포함 (직접 방문 안내).

```markdown
## {N}. 참고 링크

- [잡플래닛 {회사명} 면접후기](URL)
- [잡코리아 {회사명} 면접 질문](URL)
- [캐치 {회사명} 면접후기](URL)
- [블라인드 {회사명} 면접](URL)
- [{기타 수집된 링크}](URL)
```

### Step 6: 파일 저장

생성된 문서를 현재 작업 디렉터리에 저장한다.

파일명 형식: `{회사명}_{포지션명}_면접준비.md`

```
예: 안랩_SW배포서비스개발_면접준비.md
예: 토스_백엔드엔지니어_면접준비.md
예: 카카오_프론트엔드개발자_면접준비.md
```

저장 후 사용자에게 알린다:

```
문서가 저장되었습니다: ./{회사명}_{포지션명}_면접준비.md

[리서치 요약]
- 수집된 면접 후기: [건수 또는 "정보 부족"]
- 주요 출처: [목록]
- 생성된 예상 질문: [총 개수]개
- [차단된 사이트가 있는 경우] 일부 사이트는 직접 방문이 필요합니다: [목록]
```

## 문서 품질 기준

생성된 문서는 아래 기준을 충족해야 한다:

```
분량:
  - 예상 질문 총 15개 이상
  - 각 섹션 최소 3개 이상의 질문
  - 전체 문서 200줄 이상

내용:
  - 모든 필수 기술 스택 커버
  - 모든 질문에 <details> 답변 가이드 포함
  - 실제 후기 데이터 반영 (수집 가능한 경우)
  - 회사/포지션 특화 내용 포함 (일반적 내용만 있으면 안 됨)

형식:
  - 목차 포함
  - 헤더에 면접 메타 정보 (형태/분위기/난이도)
  - <details> 블록으로 답변 가이드 접기
  - 코드 예시 또는 비교표가 필요한 곳에 적극 활용
```

## 웹 리서치 실패 처리

| 실패 유형 | 처리 방법 |
|----------|----------|
| WebFetch 차단 (잡플래닛, 블라인드 등) | 검색 스니펫 텍스트만 활용. 링크는 참고 링크에 포함 |
| WebSearch 결과 없음 | 공고 분석 + 포지션 일반 기준으로 대체 |
| 회사 정보 부족 | 공고 텍스트에서 최대한 추출. "회사 정보 미확인" 명시 |
| URL 자체 없음 (붙여넣기만 제공) | 회사명으로 WebSearch 진행 |

**어떤 실패 상황에서도 문서 생성은 완료한다.** 리서치 실패는 문서 내 해당 섹션에 "리서치 정보 부족 — 실제 후기는 [사이트명]에서 직접 확인하세요."로 명시한다.

## 주의사항

- **자기완결형 문서**: 사용자가 다른 자료 없이도 이 문서만으로 면접 준비가 가능해야 한다
- **개인화 안내**: 답변 가이드는 방향을 제시하는 것이며, 실제 답변은 본인의 경험으로 채워야 함을 각 섹션 상단에 명시
- **후기 기반 강조**: 실제 후기에서 수집된 질문은 "(실제 후기에서 수집)" 표기
- **꼬리질문 대비**: 모든 기술 질문 답변 가이드에 최소 2개의 꼬리질문을 포함
- **리서치 한계 투명성**: 차단된 사이트나 정보 부족 영역은 문서에 명시
- **포지션 레벨 반영**: 경력 요건에서 주니어/미드/시니어를 파악하여 질문 난이도 조정
- **한국어로 작성**: 문서 전체를 한국어로 작성. 기술 용어는 영문 병기 가능
