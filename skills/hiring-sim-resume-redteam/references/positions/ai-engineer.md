# AI Engineer (LLM/ML 응용) — 시장 기대 역량 (엔진 D)

> 사용 규칙·공통 기준은 `../position-competency-map.md` 참조. 여기선 AI 엔지니어 직군만.

**핵심 기대 역량**
- **LLM 앱·RAG**: chunking·embedding 전략, 벡터 검색(ANN)·**하이브리드(BM25+vector)**·re-ranking, 컨텍스트 구성, 프롬프트 엔지니어링.
- **평가·신뢰성**: **eval 파이프라인**(정답셋·지표), 할루시네이션을 *측정*하는 법, citation·가드레일, 재현성.
- **벡터 DB 운영**: 인덱스 파라미터·recall/latency 트레이드오프, 스케일.
- **서빙·추론 최적화**: latency/throughput, 배칭, 캐싱(프롬프트/응답), 양자화·GPU, 비용(토큰) 관리.
- **MLOps**: 실험 관리, 데이터/모델 버저닝, 파이프라인, 배포 후 모니터링·드리프트.
- **데이터 파이프라인**: 수집·정제·라벨링, 피처.
- **모델링 기초(직무 따라)**: 파인튜닝(LoRA)·평가지표, 논문 이해.

**깊이 공백 신호**: "RAG로 할루시네이션 차단"인데 **어떻게 측정·평가했는지 없음**(가장 흔한 공백) · 벡터DB "썼다"만, 인덱스/recall 고민 없음 · 비용·latency 언급 0.

**공백 시 후속질문**: "할루시네이션이 줄었다는 걸 어떤 지표·정답셋으로 측정했나요?" · "검색이 틀린 문서를 가져오면요? re-ranking/hybrid는?" · "토큰 비용·응답 지연은 어떻게 관리했나요?" · "eval은 어떻게 자동화했나요?"
