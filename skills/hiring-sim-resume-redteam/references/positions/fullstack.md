# Fullstack Engineer — 시장 기대 역량 (엔진 D)

> 사용 규칙·공통 기준은 `../position-competency-map.md` 참조. 여기선 풀스택 직군만. (백엔드/프론트 세부는 필요 시 `backend.md`·`frontend.md` 추가 참조.)

**핵심 기대 역량**
- **백엔드 핵심**: API 설계(REST/GraphQL), DB 모델링, 인증/인가, 트랜잭션.
- **프론트 핵심**: SPA/SSR, 상태관리, 렌더링 성능.
- **E2E 기능 오너십**: 기획→구현→배포→운영까지 한 기능을 끝까지.
- **DevOps 기본**: CI/CD, Docker, 클라우드 배포, 환경 분리.
- **양단 성능·관측성**: 프론트 CWV + 백엔드 지연/처리량을 함께.
- **경계 판단**: 로직을 프론트/백엔드/DB 중 어디에 둘지 트레이드오프.

**깊이 공백 신호**: 한쪽(주로 프론트 또는 백)만 깊고 반대편은 이름만 · "풀스택"인데 배포·운영 흔적 없음 · 기능 하나를 끝까지 소유한 서사 부재.

**공백 시 후속질문**: "이 기능을 프론트부터 배포까지 혼자 다 했나요? 경계는 어떻게 나눴나요?" · "성능 문제가 프론트인지 백인지 어떻게 구분했나요?"
