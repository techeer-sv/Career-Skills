# Embedded Engineer — 시장 기대 역량 (엔진 D)

> 사용 규칙·공통 기준은 `../position-competency-map.md` 참조. 여기선 임베디드 직군만.

**핵심 기대 역량**
- **C/C++·리소스 제약**: 메모리 footprint, 정적 할당, 실시간 제약(deadline·jitter), 최적화.
- **RTOS/bare-metal**: 태스크 스케줄링, 인터럽트(ISR), 동기화(뮤텍스/세마포어), 우선순위 역전.
- **하드웨어 인터페이스**: I2C/SPI/UART/GPIO/ADC, 디바이스 드라이버, 데이터시트 독해.
- **저전력**: 슬립 모드·전력 프로파일.
- **통신 프로토콜**: CAN/LIN(차량), BLE/Zigbee, MQTT, 펌웨어 OTA.
- **디버깅·계측**: JTAG/SWD, 오실로스코프·로직 애널라이저, 트레이스.
- **품질·안전**: HIL 테스트, 단위테스트, MISRA·정적분석, (분야별) 기능안전 인증.
- **툴체인**: 크로스 컴파일, 링커 스크립트, 부트로더.

**깊이 공백 신호**: 앱단 코드만 있고 하드웨어·타이밍·인터럽트 언급 없음 · "임베디드"인데 실제 보드·주변장치·오실로스코프 흔적 부재 · 리소스/전력 제약 고민 없음.

**공백 시 후속질문**: "어떤 MCU·RTOS였고 실시간 제약은 어떻게 맞췄나요?" · "인터럽트와 메인 루프의 동기화는?" · "메모리/전력 제약을 어떻게 다뤘나요?" · "HW 이슈를 뭘로 디버깅했나요?"
